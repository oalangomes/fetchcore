# Retrieval

The current backend-neutral port receives `SearchIntent`, `SearchScope`, and `SearchRequirement` values and returns `KnowledgeSearchResponse` with `SearchResult` evidence. `SearchIntent` preserves canonical query text, explicit required anchors/boolean structure, caller-provided expansions, hints, typed signals and legacy terms. `SearchScope` carries repository, revision, paths, mode, result budget, settings, and optional retrieval configuration. These are acquisition inputs, not consumer satisfaction rules.

Current acquisition paths include local lexical scanning, backend lexical/BM25 retrieval, dense vector retrieval, and backend hybrid retrieval where capabilities allow. Hybrid combines lexical or sparse and dense candidates with RRF as the configured baseline. Post-acquisition reranking is optional and bounded by an explicit window. Capability checks reject unsupported modes; scores remain observations with match evidence and provenance.

Declared anchors and boolean groups are translated by capable lexical adapters, with explicit rejection by incapable channels. Native lexical analysis remains a backend responsibility. The current `mode="targeted"` and legacy exact terms do not implement a general identifier-first targeted router. That router, adaptive budgets, graph expansion and federated fusion remain future work. See [search intent](../concepts/search-intent.md) and [capabilities](../reference/capabilities.md).

The serving application attempts [targeted exact acquisition](../concepts/targeted-retrieval.md) through an optional backend port before broad retrieval. Deterministic source identity permits bounded early return; fallback preserves required exact keys through observable post-filtering.

`retrieval/projection_matching.py` owns the shared interpretation of Projection v3 fields for queries: signal to field mappings, boosts, matching and evidence derivation, retrieval controls, score normalization, and bounded diagnostics. It depends on Projection's stable record representation and version. Projection compilation and hydration do not depend on retrieval contracts. The historical Projection semantics paths alias the retrieval module for import compatibility.
